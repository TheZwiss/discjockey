# CLI audit supplement C (issue 39): 37 Library screen states no audit named

Evidence, not a design. These are the Library shot names (`hub-ui/src/pages/library/shots.json`) that a script found in
no audit file. How `docs/2026-11-14-cli-audit-library.md` section 3 treats states: a state is **Data** when it shows
something an agent needs (a value, a list, a reason, a decision), and **View** when it is only the window's own state
(an open panel, a menu, a scroll, a width, the player). Fake scenarios are in `hub-ui/src/pages/library/fake.ts`;
every scenario's data is what the real bridge returns for the same library, so the "Read" column is the real method.

Reads used (all `HubApi` methods, `discjockey/hub/api.py`): `library(view, key, query, filter, sort)` (`view`
`all|unlisted|playlist|folder`; `filter` `all|lossless|good_lossy|weak|fake|upgrade_ready`; `sort` a key, `-` in front
for descending; answer `rows[]`, `summary`, `chips`, `songs`, `empty`, `read_at`, `also`), `track(id)` (one track's
details incl. `file_state`, `playlists`, `source_how`, `upgrade`, `aiff`), `spectrum(id, which)`, `sidebar()`.
**Command today** is every console command that prints that data. There is no console read of the library at all
(audit library finding 1); the only near commands are `convert|rename <key> --dry-run --json` (the AIFF plan),
`rekordbox preview <key>` (what Same track / Convert / Rename would do), `upgrade list` (parked upgrades) and
`batch list|show`. None of them prints the facts below, so "none" means exactly that.

## What this adds to the library audit

- Of the 37 states, 24 carry data an agent needs and no command prints it (every one answers to `library(...)`,
  `track(id)`, `sidebar()` or `spectrum(id)`); 1 (`library-inspector`) is partly covered by `upgrade list`.
- 12 are view states only (open panel, hidden preference, width, menu, player, drawing of many rows or long names);
  each is listed with why it holds nothing an agent needs.
- Two surprises: `file_missing` ("This file isn't there any more.") is only ever visible through `track(id)`,
  never through a `library()` row, so a console `library` list would say `here` for a deleted file unless it asks the
  disk per file; and `library()` has no paging, so a big library (`library-big`) printed as a console list is one very
  long answer.
